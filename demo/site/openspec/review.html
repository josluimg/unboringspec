Add invite link revocation

6 requirement changes 4 decisions 8 tasks 3 open questions

Album owners can revoke and expire invite links and remove any photo, replacing today's permanent links.

  • Revoking rotates the album token: every outstanding link dies at once and a new one is issued.
  • Links get an expiry; the default lifetime is still undecided.
  • Breaking: permanent links are removed and existing ones expire 30 days after release.
  • Owners can delete any member's photo; members only their own.
  • Owners are emailed 3 days before a link expires.

decide

Remove permanent links, expire existing ones after 30 days

Breaking change: permanent invite links go away; links created before release expire 30 days after it.

Why: Permanent links cannot be revoked and are the product's main privacy risk.

Instead of: Keep permanent links but allow revocation

Risk: Families relying on an old link lose access without noticing; the 30-day grace period is fixed before the default lifetime is decided.

2 · Decisions worth a look

review

Revoke by rotating the token

Revoking replaces the album's token with a new random one instead of keeping a denylist.

Why: A denylist grows forever and must be checked on every join.

Instead of: Denylist of revoked tokens

Risk: Rotation also kills legitimate links already shared with relatives.

review

Only owners moderate photos

The owner can delete any photo; members can delete only their own.

Why: Closes the abuse path of open upload links.

Risk: Deleted photos disappear for everyone, with no undo or audit trail specified.

1 routine decisions
routine

Expiry stored next to the token, lifetime from configuration

Each token has an expires_at; the default lifetime is a configuration value.

Why: The lifetime can change without a migration.

3 · Risks

medium

Migration hard-codes 30 days while the default lifetime is open

Impact: If the team picks 7 or 90 days, existing and new links follow different rules.

Mitigation: Derive the migration expiry from the configured default, or decide the default first.

medium

The expiry email promises an action nobody builds

Impact: The notification offers a button to extend the link, but no requirement or task covers extending.

Mitigation: Add an 'Extend invite link' requirement and task, or drop the button from the scenario.

low

No tasks for tests

Impact: Rotation, expiry and the migration change access control with no planned verification.

Mitigation: Add contract tests for rotate and expired join, and a migration test.
